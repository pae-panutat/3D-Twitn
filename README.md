# Energy Building — เมือง 3D และศูนย์ควบคุมการเดินรถจำลอง

เวอร์ชัน 2.0 ใช้ Next.js + TypeScript + React Three Fiber + Three.js/Drei และ Node.js Backend + SSE โมเดล glTF, ข้อมูล geometry และตัวจำลองเดิมไม่ได้แก้ไข อ่านรายละเอียดการย้ายและผลการตรวจโมเดลใน [MIGRATION.md](MIGRATION.md)

ปรับตามแนวเว็บ https://bangkokbts.whisperingweekends.com/ ที่ผู้ใช้ส่งมา: ฉากเมืองริมแม่น้ำเต็มจอ โทนขาว–น้ำเงิน แผงข้อมูลลอย สถานี 4 แห่ง ขบวนรถ 6 ขบวน และข้อมูลที่เปลี่ยนตามการจำลอง

โมเดลและโค้ดเขียนขึ้นใหม่ ชื่อสถานีอ้างอิงพื้นที่จริง แต่ตำแหน่งอาคาร ระยะทาง รถไฟ สัญญาณ และตัวเลขทั้งหมดเป็นตัวอย่างจำลอง ไม่มีข้อมูลสดจาก BTS

ใช้ฟอนต์ Kanit แบบเก็บไฟล์ไว้ในเว็บไซต์ รองรับน้ำหนัก 400/500/600/700 พร้อมใบอนุญาต SIL OFL ใน `dist/fonts/` ขนาดข้อความและแผงปรับไว้ใน `dist/typography.css` ฉากกลางวันมีแสงแดดโทนอุ่น แสงสะท้อนจากท้องฟ้า และเงาทอดบนพื้น

มุมมองเริ่มต้นแสดงเมืองพร้อมหมุน 360° อัตโนมัติ เปิดแผงข้อมูลด้านขวาที่แท็บภาพรวมและแถบควบคุมล่างซ้ายไว้ มีแท็บภาพรวม วัตถุ ตาราง และเหตุการณ์ คลิกโมเดลหรือป้ายชื่อเพื่อเปิดแท็บวัตถุ กดปุ่มปิดหรือ Escape เพื่อยุบแผง แล้วกด “แผงข้อมูล” เพื่อเปิดกลับ

## เปิดบนเครื่อง

ใช้ Node.js 20.9 ขึ้นไป ติดตั้ง dependencies และ build ก่อนรัน production

```sh
cd siam-twin
npm install
npm run build
npm start
```

เปิด http://127.0.0.1:4173 หรือบน Mac ดับเบิลคลิก `start.command` แล้วเปิด URL นี้ในเบราว์เซอร์ แอปต้องทำงานผ่าน Node.js server ไม่ใช่เปิดไฟล์ซอร์สด้วย `file://`

สำหรับการพัฒนาใช้ `npm run dev` หน้า Next.js รับข้อมูลจาก Node.js Backend ด้วย SSE ทุก 0.5 วินาที คำสั่งควบคุมมีผลร่วมกันสำหรับหน้าต่างที่เชื่อมเซิร์ฟเวอร์เดียวกัน ไม่มี fallback ไปตัวจำลองใน browser

## ทดลองอะไรได้บ้าง

- หมุน ซูม และเลื่อนกล้องในฉากเมือง low-poly ที่สร้างด้วย WebGL
- เปิดเว็บด้วยมุมภาพรวมเฉียงเล็กน้อยตามภาพอ้างอิง พร้อมหมุน 360° อัตโนมัติและแถบควบคุมล่างซ้ายที่เปิดไว้ กด “หมุน 360°” เพื่อหยุด/เริ่ม หรือจับลากโมเดลเพื่อหยุดหมุนและควบคุมกล้องเอง
- เมืองริมแม่น้ำ สถานีวงเวียนใหญ่ กรุงธนบุรี สะพานตากสิน สุรศักดิ์ ลานซ่อม และท่าเรือสาทร
- เลือกสถานีและขบวนจากโมเดล ป้ายชื่อ ช่องค้นหา หรือตารางด้านล่าง
- ตารางขบวนรถ 6 ขบวน / สถานี 4 แห่ง / สัญญาณ 8 จุด ในแผงด้านขวา
- แผงรายละเอียด ความเร็ว สถานีถัดไป เวลาถึง ความหนาแน่น และขั้นตอนการเดินทาง
- รถไฟวิ่งตาม snapshot เดียวกับข้อมูลบนจอ และกลับทิศเมื่อถึงปลายทาง
- ติดตามขบวน พักขบวนที่สถานีถัดไป และปล่อยเดินรถต่อ
- หยุดเวลา ความเร็ว 1×/3× หมุนชมเมืองอัตโนมัติ
- กลางวัน/กลางคืน แสง ความสว่าง ฝน หมอก และฉากเทศกาล
- แผนภาพเส้นทาง ปุ่มเปิด OpenStreetMap และการส่งออก CSV
- ส่งออกโมเดลเมืองเป็น glTF พร้อม geometry ฝังในไฟล์
- แสดงผล Desktop / Tablet / Mobile และสถานะข้อมูลขาดการเชื่อมต่อ

แป้นพิมพ์: โฟกัสพื้นที่ 3D แล้วใช้ลูกศร, +/−, Home และ Space เพื่อหยุด/เปิดเวลา ปุ่ม / โฟกัสช่องค้นหา การเลื่อนกล้องใช้คลิกขวาลากหรือ Shift + ลาก บนจอสัมผัสใช้หนึ่งนิ้วหมุนและสองนิ้วจีบเพื่อซูม

## ต่อ API จริง

เริ่มจากกำหนดรหัสขบวน สถานี และสัญญาณให้ตรงกันระหว่างโมเดลกับข้อมูล ตัวอย่างใช้ BTS-1101 ถึง BTS-1106, S8 ถึง S5 และ SIG-<สถานี>-<ทิศทาง>

รุ่น Next.js เรียก `/api/*` ที่ origin เดียวกัน เปลี่ยน adapter ใน `backend/api.mjs` เมื่อต้องการต่อระบบจริง โดยเก็บ API keys และ secrets ที่ backend เท่านั้น ตัว API ต้องให้ snapshot schema รุ่น 2 ตาม `CitySimulation.snapshot()` และ endpoints:

| Endpoint | หน้าที่ |
| --- | --- |
| GET `/api/health` | ระบุ `{service: 'siam-city', source: 'simulation', transport: 'sse'}` สำหรับตัวอย่าง |
| GET `/api/snapshot` | Snapshot เต็ม: timestamp, metrics, trains, stations, signals, events, rate, paused, elapsed |
| GET `/api/events` | SSE `data: <snapshot JSON>\n\n` ทุก 0.5 วินาที |
| POST `/api/control` | ตัวจำลองเท่านั้น: `{action: 'pause'}`, `{action: 'rate', value: 3}`, `{action: 'hold', id: 'BTS-1101'}`, `{action: 'reset'}` |

เมื่อต่อข้อมูลจริง ให้แทน `CitySimulation` ด้วย adapter อ่านระบบของคุณ ปรับ `validCitySnapshot` ให้รับ `source: 'live'` เปลี่ยนข้อความ “ข้อมูลจำลอง” และแยกหรือปิดคำสั่งควบคุมการจำลอง การเชื่อม API ที่ตั้งค่าไว้แล้วล้มเหลวจะแสดงข้อความขาดการเชื่อมต่อและลองใหม่ โดยไม่สลับไปข้อมูลจำลองเงียบ ๆ

ใช้ WebSocket แทน SSE ได้โดยปรับ `src/lib/useTelemetry.ts` และเพิ่ม endpoint ใน backend ส่วน MQTT ควรผ่าน backend/gateway เพื่อเก็บการเชื่อมต่อและ credentials ฝั่งเซิร์ฟเวอร์ รุ่นปัจจุบันใช้ SSE

หากต้องการประวัติถาวรหรือระบบหลายผู้ใช้ ให้เพิ่มฐานข้อมูลและระบบสิทธิ์ รุ่นนี้เก็บข้อมูลใน memory และไม่มีฐานข้อมูล PostgreSQL ที่ติดตั้งแล้ว

## โมเดลจริง

แก้ `createCity()` และ `createTrain()` ใน `city.js` แล้วรัน `npm run model` หน่วยโมเดลเป็นเมตรและแกน +Y ขึ้น แต่ระยะทางในฉากถูกย่อและไม่ใช่ระยะสำรวจจริง โมเดล GLB/IFC ภายนอกต้องเพิ่ม loader เช่น Three.js/That Open และเชื่อมรหัสวัตถุกับ snapshot รุ่นนี้ยังไม่มีการอัปโหลดโมเดลภายนอก

## ข้อจำกัด

ต้นแบบนี้ไม่ใช่ระบบควบคุมรถไฟจริง สัญญาณแสดงขบวนที่อยู่ใกล้จุดตรวจ ไม่ใช่ระบบ interlocking ที่รับรองความปลอดภัย กำหนดช่วงเวลาและตัวเลขขึ้นเพื่อทดลอง การพักขบวนไม่ใช่คำสั่งส่งไป BTS

ข้อมูล server อยู่ได้เฉพาะระหว่าง process เปิดอยู่ รุ่น Next.js ต้องโฮสต์บนบริการที่รัน Node.js ต่อเนื่องเพื่อเปิด SSE และยังไม่มีบัญชีผู้ใช้ ฐานข้อมูลถาวร IoT จริง หรือประวัติผู้โดยสารจริง โมเดล low-poly เขียนขึ้นเองและไม่ใช่สำเนาโมเดลของเว็บไซต์อ้างอิง
